# Как работать с Pantry Pilot

Спасибо за участие в разработке Pantry Pilot. Этот документ описывает общий процесс работы команды и минимальные требования к изменениям.

## Подготовка окружения

Понадобится Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev
```

Перед началом работы убедитесь, что проект запускается, а исходные проверки проходят.

## Работа над задачей

Команда придерживается следующего процесса:

1. Выберите одну Issue и уточните ожидаемое поведение.
2. Воспроизведите проблему до изменения кода.
3. Зафиксируйте гипотезу о причине.
4. Внесите минимальное изменение, необходимое для решения задачи.
5. Добавьте регрессионный тест, если ошибка может незаметно вернуться.
6. Проверьте изменение и отправьте его на ревью.
7. После успешного ревью создайте коммит и Pull Request.

Не объединяйте в одном Pull Request несвязанные исправления, рефакторинг и форматирование.

## Проверки качества

Перед отправкой изменений выполните:

```bash
npm run check
npm run build
```

Отдельные команды:

```bash
npm run format:check
npm run lint
npm run typecheck
npm test
```

Для автоматического форматирования и безопасных автоматических исправлений доступны:

```bash
npm run format
npm run lint:fix
```

После автоматических исправлений обязательно просмотрите diff и повторно запустите проверки.

## Требования к изменениям

- Сохраняйте существующее поведение за пределами выбранной задачи.
- Не меняйте публичные форматы данных без продуктового согласования.
- Предпочитайте понятные имена и небольшие функции сложным комментариям.
- Не добавляйте зависимости, если задачу можно ясно решить средствами текущего стека.
- В описании Pull Request укажите проблему, способ проверки и добавленные тесты.

## Pull Request

Pull Request должен быть небольшим и готовым к проверке. В описании добавьте:

- ссылку на Issue;
- краткое объяснение изменения без пересказа всего diff;
- шаги ручной проверки;
- результаты автоматических проверок;
- известные ограничения, если они остались.
